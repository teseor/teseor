# ADR-0007 — Astro for the docs site

- **Status:** Accepted.
- **Deciders:** repo owner (letanure).

## Decision

The docs site (`apps/docs/`) is built with **Astro** — plain Astro, no Starlight
or any themed doc framework. The site styles itself entirely with Teseor's own
`.t-*` classes and renders Teseor's component packages (`@teseor/react`, later
others) directly. This supersedes the Eleventy + Nunjucks choice previously
recorded in `architecture/docs-site.md`.

## Why Astro and not the alternatives

- **Not Eleventy + Nunjucks (the prior choice).** Eleventy cannot render the
  DS's component packages. Putting a Teseor Button in the docs would mean
  hand-writing `.t-button` markup as a Nunjucks macro — a second implementation
  of every component, in another language, drifting from the codegen-generated
  wrapper. That parallel system is exactly what the dogfood rule forbids.
  Eleventy dogfoods only the CSS layer.
- **Not Astro + Starlight / Vitepress / Docusaurus.** Still rejected: each ships
  an opinionated theme that fights the dogfood rule. The prior doc conflated
  "Astro" with "Astro + Starlight" — plain Astro ships no theme.
- **Astro renders the real packages.** `import { Button } from "@teseor/react"`
  renders to static HTML at build time, zero client JS unless a `client:*`
  directive opts in. The docs' Button *is* the generated wrapper — one
  implementation, regenerated by codegen, no drift. The docs become a genuine
  consumer of the published packages: the strongest form of dogfooding.

## Consequences

- `apps/docs/` carries Astro + `@astrojs/react` as dependencies — heavier than
  Eleventy, but the build-time component rendering is the entire point.
- `architecture/docs-site.md` is updated to match: Astro replaces Eleventy +
  Nunjucks; the themed-framework rejection is scoped to Starlight et al.
- `gen-docs` (#560) emits structured data the Astro site consumes. The data is
  SSG-agnostic, so the generator design is unaffected beyond the consumer.
- Shiki (built into Astro), Pagefind, and Cloudflare Pages deployment carry over
  unchanged — none were Eleventy-specific.
