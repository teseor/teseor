# ADR-0012 — Wrapper-internal seam: generated `_runtime.ts` + framework-conventional folders

- **Status:** Accepted.
- **Deciders:** repo owner (letanure).

## Decision

Each wrapper package (`packages/react/`, `packages/vue/`, future
`packages/svelte/`, ...) splits its internal source between one
generator-emitted runtime file and framework-conventional folders for
hand-authored code. Files are placed by origin and concern:

| Path | Origin | Holds |
| --- | --- | --- |
| `packages/react/src/_runtime.ts` (and the Vue parallel `packages/vue/src/_runtime.ts`) | Generated by `codegen/src/generators/gen-react.ts` (or `gen-vue.ts`) | Mechanical helpers driven by `specs/_breakpoints.yaml`: `RESPONSIVE_KEYS`, `Responsive<T>`, `BREAKPOINT_QUERIES`, `useActiveBreakpoint`, `isActiveAt`, `resolveResponsive`, `responsiveDataAttrs`, `asElement` |
| `packages/react/src/hooks/useOverlay.ts` (and `packages/vue/src/composables/useOverlay.ts`) | Hand-authored | Cross-cutting framework-idiomatic library code: `useOverlay`, plus future `useEscapeStack`, `useFocusTrap`, `useOutsideClick`, etc. One concern per file. |
| `packages/react/src/components/Slot.tsx` (and `packages/vue/src/components/Slot.ts`) | Hand-authored | Cross-cutting framework-idiomatic library components: `Slot`. One concern per file. |
| `packages/react/src/behavior/<name>.tsx` (and the Vue / Svelte parallels) | Hand-authored | Per-component stateful behavior (Combobox keyboard handling, Tabs roving tabindex, etc.) imported by the matching generated styling shell when `behavior !== none` (see `docs/architecture/codegen-pipeline.md`). |
| `packages/react/src/Button.tsx`, `packages/vue/src/Button.vue`, ... | Generated | One wrapper per spec. |

Folder names follow each framework's ecosystem convention — **hooks** for
React, **composables** for Vue — so file paths read the way a contributor
from that ecosystem expects.

## Why this and not the alternatives

- **Not "everything generated."** The pre-#665 layout embedded `Slot`,
  `useOverlay`, and ~250 lines of behavior inside a backtick template in
  `codegen/src/generators/gen-react.ts`. The output banner said
  *"Do not edit"* but the code was hand-shaped; debugging meant editing a
  template literal with no type-checking. Hostile contract.
- **Not flat `_overlay.ts` / `_slot.ts`.** Considered. Smaller diff, but
  doesn't pay back as the hook count grows (#675 overlay orchestration
  adds three more). One-hook-per-file in a conventional folder reads
  better at five files than at two, and the seam stays the same.
- **Not "move it all to `@teseor/primitives` now."** The headless package's
  shape is still settling; framework-specific hooks (`useOverlay` uses
  React `useState` / `useEffect`, Vue `ref` / `watch`) don't fit a
  framework-agnostic package until the wrapper-agnostic core is factored
  out. This layout is the interim step; eventual primitive extraction can
  hoist files out of the per-package hooks / composables folders without
  disturbing wrapper consumers.
- **Not unifying React + Vue folder names.** *hooks* is the React idiom;
  *composables* is the Vue idiom. Aligning them on one name reads as
  foreign in the other ecosystem. The generator carries the per-framework
  branch.

## Consequences

- **Generators emit smaller `renderRuntime` templates.**
  `codegen/src/generators/gen-react.ts` and
  `codegen/src/generators/gen-vue.ts` produce only the mechanical
  `_runtime.ts` bits; the hand-authored modules are reviewed as real code.
- **`gen-drift` enforces the gen / hand seam by path.** Anything under
  the per-framework hooks / composables / components / behavior folders
  is not regenerated, so `pnpm gen && git diff --exit-code` passes
  regardless. The drift gate protects only files that carry the
  `AUTOGENERATED` banner.
- **Tests colocate with the file they cover.**
  `packages/react/src/hooks/useOverlay.test.tsx` sits next to
  `packages/react/src/hooks/useOverlay.ts`;
  `packages/react/src/components/Slot.test.tsx` next to
  `packages/react/src/components/Slot.tsx`. The monolithic per-package
  `_runtime.test.{tsx,ts}` shrinks to cover the generated mechanical
  helpers only.
- **Public API unchanged.** `packages/react/src/index.ts` and
  `packages/vue/src/index.ts` continue to re-export only the generated
  wrappers (`Button`, `Tooltip`, ...). `useOverlay`, `Slot`, and
  mechanical helpers stay package-internal.
- **Future wrappers follow the same shape.** A future `packages/svelte/`
  uses whatever the Svelte ecosystem settles on for shared composables;
  a future `packages/webc/` uses whatever the LitElement ecosystem
  expects. The generator-emitted `_runtime.ts` vs hand-authored-folder
  seam carries across.
