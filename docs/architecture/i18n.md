# i18n

`@teseor/i18n` is a lightweight internationalization layer for **component-internal messages** — ARIA labels, error states, default button text ("Close", "Loading…"), placeholder strings. It is not a general application i18n framework. Apps that need full i18n stay with their existing solution (FormatJS, lingui, i18next, etc.) and pass translated strings into Teseor components as props.

## Scope

- ~50 lines of typed TypeScript, no runtime dependencies
- ICU MessageFormat subset (three features only)
- Per-locale direction metadata
- Catalog-as-data: importable per-locale, tree-shakable
- ≤ 1KB gz for the core; catalogs are separate

We rejected `intl-messageformat` (~12KB), `react-intl` (~50KB), `lingui` (~30KB) for the same reason: their feature surface is much larger than component-internal messages need, and Teseor must stay small.

## ICU subset

Three features. Anything else is the application's problem.

**Interpolation:**
```
"Hello, {name}"
```

**Plural** (CLDR plural categories: `zero`, `one`, `two`, `few`, `many`, `other`):
```
"{count, plural, one {# item} other {# items}}"
```

**Select** (string discrimination):
```
"{gender, select, male {him} female {her} other {them}}"
```

Skipped from full ICU:
- Number / date / time formatting — use `Intl.NumberFormat` and `Intl.DateTimeFormat` directly at the call site. More standard, locale data is built into the JS engine.
- `spellout`, `ordinal`, `duration` — rare.
- `choice` — deprecated in CLDR.

## Locale shape

```ts
type Locale = {
  meta: {
    direction: "ltr" | "rtl";
    lang: string;       // BCP 47 tag, e.g. "ar", "ar-SA", "en-US"
  };
  messages: Record<string, string>;
};
```

Example:

```ts
// packages/i18n/locales/ar.ts
export const ar: Locale = {
  meta: { direction: "rtl", lang: "ar" },
  messages: {
    close: "إغلاق",
    loading: "جار التحميل…",
    "items.count": "{count, plural, zero {لا توجد عناصر} one {عنصر واحد} two {عنصران} few {# عناصر} many {# عنصرًا} other {# عنصر}}",
  },
};
```

## API

```ts
export function setLocale(name: string): void;     // also sets <html dir lang>
export function getLocale(): string;
export function t(key: string, vars?: Record<string, string | number>): string;
```

Behavior:

- `t("close")` returns the current locale's `messages.close`, or `en.messages.close` if missing, or the key itself if both are missing.
- `t("items.count", { count: 3 })` formats plural through the subset implementation.
- `setLocale("ar")` mutates a module-level variable AND writes `dir="rtl" lang="ar"` to `document.documentElement`.

Components consume `t` directly:

```tsx
// Inside a generated Button wrapper
<button aria-label={loading ? t("loading") : undefined} {...rest}>
  {children ?? t("button.default")}
</button>
```

## Direction is per-locale, not per-message

The text direction (`ltr` / `rtl`) lives in `locale.meta.direction`. Messages themselves are just strings. The locale loader sets `<html dir>`; logical CSS properties (hard rule 5) handle visual mirroring everywhere.

No per-message direction field. No "RTL fork" of a message. Components don't read direction directly — they read logical CSS properties, which the browser resolves based on `dir`.

## Catalog tree-shaking

Catalogs are individual modules. Apps import the ones they need:

```ts
import { setLocale, t } from "@teseor/i18n";
import { en } from "@teseor/i18n/locales/en";
import { ar } from "@teseor/i18n/locales/ar";

registerLocale(en);
registerLocale(ar);
setLocale(navigator.language.startsWith("ar") ? "ar" : "en");
```

Bundlers strip unimported catalogs. The core (`setLocale`, `t`, `registerLocale`, plural formatter) is the only mandatory cost — ≤ 1KB gz, enforced by `size-limit`.

## What `@teseor/i18n` is NOT

- Not a replacement for FormatJS / lingui / i18next for application content
- Not a translation management system — catalogs are hand-edited TS files
- Not a date/time/number formatter — use `Intl.*` directly
- Not a route-aware locale switcher — that's app-layer concern

If a Teseor consumer already runs a heavier i18n stack, they pass translated strings into components as props and never touch `@teseor/i18n`. The package only matters for consumers who want sensible defaults out of the box.
